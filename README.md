# 🧭 Сайт-презентация Владимира Скворцова

Персональный сайт системного аналитика, архитектора решений и эксперта по кибербезопасности: опыт, профессиональная экспертиза, примеры задач и контакты для связи.

**Стек:** Next.js (App Router), React, TypeScript, SCSS Modules.

## 🚀 Запуск и проверка

Требуется Node.js. Откройте проект в VS Code и выполните в терминале:

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

Проверка и запуск production-сборки:

```bash
npm run typecheck
npm run build
npm run start
```

`npm run build` создаёт production-сборку с Webpack; `npm run start` запускает её после сборки.

Форматирование исходного кода и проверка единого стиля:

```bash
npm run format
npm run format:check
```

Настройки Prettier находятся в `.prettierrc.json`: отступ — два пробела. Их также можно использовать в VS Code с расширением Prettier.

## 🔎 Поисковая оптимизация

Для главной страницы настроены заголовок и описание, канонический адрес, карточка ссылки для социальных сетей и структурированные данные профиля. Карта сайта доступна по адресу `/sitemap.xml`, правила для поисковых роботов — по адресу `/robots.txt`.

До запуска на собственном домене основным адресом по умолчанию остаётся `https://landing-page-presentation-sandy.vercel.app`. Для сборки на VPS задаётся `SITE_URL=https://vs-profile.ru`: адреса в метаданных, карте сайта и `robots.txt` обновятся вместе. Тексты метаданных находятся в `src/data/seo.ts`, изображение для карточки ссылки — в `public/assets/og-cover.jpg`.

### 🌐 Будущий запуск на VPS и домене REG.RU

Для сайта выбран домен **vs-profile.ru**. Основным адресом планируется `https://vs-profile.ru`, а `www` можно перенаправить на него после настройки DNS и сертификата. Адрес VPS и имя пользователя развёртывания задаются через секреты GitHub.

На сервере с Linux адрес необходимо задать **до сборки**:

```bash
npm install
SITE_URL=https://vs-profile.ru npm run build
npm run start
```

После смены `SITE_URL` сайт необходимо пересобрать. DNS, HTTPS и постоянный запуск приложения на сервере настраиваются при развёртывании.

### 🚀 Автоматическое развёртывание через GitHub

Подготовлен `.github/workflows/deploy.yml` по образцу сайта «Эксперт-Аудит»: при отправке в `main` GitHub Actions проверяет форматирование, создаёт production-сборку и проверяет типы. После успешных проверок он сможет подключаться к VPS по SSH, устанавливать зависимости, собирать тот же коммит с `SITE_URL=https://vs-profile.ru`, перезапускать службу `vs-profile` и проверять ответ сайта. Повторный запуск доступен через **Actions → Deploy to VPS → Run workflow** для ветки `main`.

До подготовки сервера развёртывание отключено: для его включения необходимо создать в настройках репозитория переменную Actions `DEPLOY_ENABLED` со значением `true`. Без неё выполняются только проверки. Перед включением потребуется:

1. Подготовить VPS с Node.js 24 и npm, установить Git, curl, Nginx и HTTPS-сертификат. Создать пользователя развёртывания и склонировать репозиторий в отдельный каталог `/var/www/landing-page-presentation`, доступный ему для записи; у сервера должен быть доступ для `git fetch` из GitHub.
2. Настроить службу systemd `vs-profile` для запуска сайта на `127.0.0.1:3100`. Пример находится в `deploy/vs-profile.service.example`: в нём нужно указать пользователя и проверить путь к Node.js/npm на сервере. Настроить Nginx как обратный прокси на этот порт и предоставить пользователю развёртывания право выполнять `sudo -n systemctl restart vs-profile`.
3. В **Settings → Secrets and variables → Actions → Secrets** добавить `VPS_HOST` (адрес VPS), `VPS_USER` (имя пользователя развёртывания), `VPS_SSH_KEY` (его приватный ключ) и `VPS_HOST_FINGERPRINT` (проверенный SHA256-отпечаток SSH-ключа сервера). Соответствующий открытый ключ должен быть добавлен на VPS.
4. Проверить DNS и сертификат, затем включить `DEPLOY_ENABLED` и запустить workflow. Убедиться, что служба работает и сайт открывается по HTTPS.

При развёртывании рабочая копия в выделенном каталоге сбрасывается к проверенному коммиту (`git reset --hard`): несохранённые изменения отслеживаемых файлов в этом каталоге будут потеряны. Секреты и настройки сервера не следует хранить в репозитории или рабочем каталоге сайта.

### 🌊 Графика первого экрана

Портрет Владимира и фон с волнами загружаются через `next/image`. Браузер видит оба изображения в исходном HTML и выбирает подходящий размер с учётом ширины экрана и плотности пикселей. Волны занимают всю ширину блока, а архитектурная схема остаётся отдельным SVG.

## 📁 Где что менять

- `src/app/` — главная страница, метаданные, шрифты и глобальные стили (`globals.scss`).
- `src/components/layout/` — шапка и подвал сайта.
- `src/components/sections/home/` — блоки главной страницы; каждый компонент находится рядом со своим `*.module.scss`.
- `src/components/ui/` — общие элементы интерфейса, в том числе векторные иконки, схемы проектов и карточки цитат.
- `src/styles/` — общие SCSS-примеси для компонентов.
- `src/data/site.ts` — контакты и ссылки на социальные сети; `src/data/resume.ts` — опыт, проекты, навыки, образование и должностные обязанности.
- `src/data/quotes.ts` — тексты цитат в разделах сайта.
- `public/assets/` — логотип и графика: `logo.svg` используется в шапке, подвале и значке вкладки; `hero-waves.webp`, `architecture.svg` и `hero-portrait.webp` оформляют первый экран.
- `public/assets/experience-portrait.webp` и `experience-portrait-mirrored.webp` — исходный и зеркальный варианты портрета для раздела опыта; нужный файл выбирается в `src/components/sections/home/Experience/Experience.tsx`. `contact-portrait.webp` — портрет для раздела контактов.
- `public/icons/` — значки для iPhone, iPad и Android; `src/app/manifest.ts` описывает Android-иконки для добавления сайта на экран устройства.
- `src/app/fonts/` — локальные шрифты IBM Plex Sans и Lora и их лицензии.
- `docs/resume-cybersecurity.md` — профиль по кибербезопасности, составленный по предоставленным документам.

Опыт, проекты, навыки, образование и должностные обязанности редактируются в `src/data/resume.ts`, контакты и ссылки — в `src/data/site.ts`. Остальные тексты находятся в компонентах соответствующих разделов. Подробности обязанностей, должностей и дополнительных программ обучения раскрываются по нажатию.
